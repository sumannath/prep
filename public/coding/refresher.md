**1. API rate limiter.** Keep a deque of accepted-request timestamps per customer, behind a `RateLimitStrategy` interface, with an injected monotonic clock and a lock. On each call, pop timestamps at least T old from the left; if fewer than N remain, append now and accept, otherwise reject without recording it. That gives an exact sliding window at amortised O(1), because each timestamp is pushed and popped once. Name the fixed-window boundary burst as the reason you didn’t pick the cheaper option. The credits follow-up is a token bucket with lazy refill, `min(cap, tokens + elapsed × rate)`. Many servers means Redis (a sorted set updated in one Lua script) and an explicit fail-open or fail-closed decision. *Time: O(1) amortised per call. Space: O(N) per active customer.*

**2. Top N collections by size.** One pass: add each file’s size to the grand total and to every distinct collection it lists (a `defaultdict`, with `set()` to dedupe). Get the top N with `heapq.nlargest`, a size-N min-heap whose top is the weakest of the current best, which costs O(C log N) instead of sorting at O(C log C); tie-break by name. For nested collections, walk parent pointers up from each of the file’s collections into an ancestor set (stop at an already-seen node), then add the size once per ancestor. Rolling child totals into parents would double count a file in two sibling collections. For live data, apply deltas along the same ancestor set. *Time: O(F·k + C log N). Space: O(C).*

**3. Design Snake game.** The body is a deque with the head on the left plus a set of occupied cells; a direction table maps U/D/L/R to deltas, and food is an advancing index. A move: compute the new head; out of bounds returns -1; if not eating, pop the tail and remove it from the set; if the head is now in the set, return -1; push the head. Eating simply skips the tail pop, which is the growth. Every move is O(1) because the middle of the body never changes. The classic bug is checking collision before freeing the tail cell. For “grow every k moves”, extract a `GrowthPolicy`; for multiplayer, move occupancy to the board. *Time: O(1) per move. Space: O(W·H) worst case.*

**4. Middleware router.** Start with a dict for exact matches, then switch to a trie keyed by path segment (split on `/`, drop empties), each node holding children and a handler. Match with DFS: try the static child first, then `:param` children (capturing into a fresh copy of the params dict) and `*` children, returning the first full match. Backtracking is essential: `/a/b/c` must fall back to `/a/*/c` when the static `b` branch dead-ends. State the precedence aloud: static beats parameter beats wildcard. Cost is O(segments) in practice. For middleware, store it on nodes, collect it along the matched path, and compose a `(request, next)` chain. *Time: O(L) typical, worse with many wildcards. Space: O(total segments).*

**5. Count votes / rank teams.** One pass over the ballots: for each of the first three names, `points[c] += 3 - rank` and `reached_at[c] = ballot_index`. The last time a candidate scores is when they reached their final total. Sort by `(-points, reached_at, name)`. LeetCode 1366 instead counts votes per position per team and sorts by the negated count vector, then the letter. O(B + C log C). Probe the spec for short ballots, duplicates and the second-level tie the rule leaves open. For a live leader under streaming votes, use a max-heap with lazy deletion. *Time: O(B + C log C). Space: O(C).*

**6. Stock price fluctuation.** A dict from timestamp to price is the source of truth; `latest` tracks the maximum timestamp, so `current()` is a lookup. On every update, push `(-price, ts)` onto a max-heap and `(price, ts)` onto a min-heap, and never delete. On `maximum()` or `minimum()`, pop tops while `prices[ts]` differs from the heap’s price (those are stale corrections), then return the top. It’s correct because every live price has a valid entry somewhere in the heap, and amortised O(log n) because each entry is popped at most once. Store the timestamp in the entry, since price alone is ambiguous. If memory grows, rebuild the heaps once stale entries exceed half. *Time: O(log n) amortised. Space: O(updates).*

**7. All O'one data structure.** Counts change by exactly ±1, so keep a doubly linked list of count buckets in ascending order (each a set of keys) between a sentinel head (count 0) and tail, plus a map from key to bucket. `inc`: if the next bucket isn’t count+1, insert one right after the current bucket, move the key there, and remove the old bucket if it’s empty. `dec` mirrors this toward the previous bucket, or drops the key at count 1. Max is `tail.prev` and min is `head.next`, so everything is O(1). Insert the destination before emptying the source, because the source is your position in the list. Top-k is a walk back from the tail in O(k). *Time: O(1) every operation. Space: O(keys).*

**8. LRU cache.** A hashmap from key to node, plus a doubly linked list ordered by recency with dummy head and tail so unlink and push-front need no edge cases. `get`: a miss returns -1; a hit moves the node to the front. `put`: an existing key is updated and moved to the front; when full, evict `tail.prev` and delete its key from the map (which is why nodes store their keys); then insert at the front. All O(1). It must be doubly linked because O(1) removal needs the predecessor. Mention `OrderedDict` as the production answer. For threads, use one lock, or shard by key hash and accept approximate global LRU. *Time: O(1). Space: O(capacity).*

**9. Time-based key-value store.** Per key, keep parallel lists of timestamps and values; timestamps arrive increasing, so they’re already sorted. `set` appends in O(1). `get` does `i = bisect_right(times, t)` and returns `values[i-1]` if `i` else an empty string. `bisect_right` places `i` after any equal timestamp, so exact matches are included; `bisect_left` is the off-by-one. Read with `.get(key, [])` so misses don’t create entries. Get is O(log n). If timestamps can arrive out of order, use `insort` or a sorted container, or insert by scanning back from the end when records are only slightly late. *Time: set O(1), get O(log n). Space: O(total sets).*

**10. Closest common group in an org chart.** For a tree, post-order DFS returns how many target employees sit in each subtree; the first group whose count equals k is the answer, because post-order finishes deeper groups before their ancestors. That’s O(n). With multiple parents (a DAG), subtree counting double counts, so BFS upward from each employee to get the distance to every ancestor, intersect the ancestor sets, and pick the group that minimises the maximum distance, tie-broken by the sum. Confirm that definition of “closest” first. That’s O(k × (V + E)). For reorgs during queries, use copy-on-write snapshots in a read-heavy org, or a read-write lock otherwise. *Time: O(nodes). Space: O(height).*

**11. Merge intervals.** Sort by start, then sweep: if the interval starts at or before the last merged end, set that end to `max(last_end, end)`; otherwise append a new interval. Sorting makes this correct because once an interval starts past the current block’s end, every later interval does too, so you only ever compare with the last block. O(n log n). The trap is assigning the new end instead of the max, which breaks on contained intervals; always test `[[1,10],[2,3]]`. Ask whether touching intervals merge. For team free time, merge everyone’s busy intervals and keep gaps of at least 30 minutes. *Time: O(n log n). Space: O(n).*

**12. Find leaves of binary tree.** A node’s removal round is its height (distance to its deepest leaf), not its depth: a node goes one round after its last child, so `height = 1 + max(left, right)` with a missing child at -1. A post-order DFS returns the height and appends the value to `rounds[height]`, adding a new list when `height == len(rounds)`, which is safe because a child of height h−1 is always visited first. O(n) time, O(h) stack. Say out loud why BFS by depth is wrong. For very deep, line-shaped trees, switch to an iterative post-order to avoid Python’s recursion limit. *Time: O(n). Space: O(h).*

**13. Number of islands.** Treat land cells as graph nodes and count connected components. Scan every cell; on unvisited land, increment the count and BFS with a deque over the four neighbours, marking cells visited when you enqueue them (not when you dequeue) so nothing is queued twice. Use a seen set if the grid mustn’t be mutated. O(R × C) time and space. Prefer iterative BFS to recursive DFS on large grids. If land is added over time, use Union-Find: each new land cell adds one island, and each successful union with a land neighbour removes one. *Time: O(R·C). Space: O(R·C).*

**14. Design file system with directory sizes.** Base version: a dict from full path to value, with the empty string pre-stored as root. `create_path` checks the path is absent and its parent (`path[:path.rfind("/")]`) is present. For sizes, use a trie of directories where each node keeps a running total; `add_file` adds the size to every directory on the path, making `dir_size` an O(depth) lookup. You pay on write because dashboards read far more than they write. Top N is a traversal plus `heapq.nlargest`. Deleting subtracts along the path; moving a directory subtracts its total from the old ancestors and adds it to the new ones. *Time: add O(depth), size O(depth), top O(D log N). Space: O(directories).*

**15. Resilient API client: rate limits and retries.** Three injected pieces: a fixed-window limiter whose `acquire_delay()` returns how long to wait, a `send` transport, and a retry loop. Retry only timeouts, connection errors, 429 and 5xx; fail fast on every other 4xx. Wait for Retry-After if the server sends it, otherwise use full jitter, `uniform(0, min(cap, base × 2^(attempt−1)))`, up to a maximum number of attempts, then raise. Log one JSON line per attempt (attempt, status, retryable). Jitter prevents synchronised retry storms. Non-idempotent POSTs need an idempotency key. Add a circuit breaker and metrics on retry and 429 rates, and treat rising 429s as a conversation with the customer. *Time: O(attempts). Space: O(1).*
