# Subsets (Power Set) — Complete Interview Lesson

## 1. Problem Restatement

You're given an array `nums` of **distinct** integers, length up to 10. Return **every possible subset**, including the empty set — i.e., the *power set*. Two rules matter:

- **No duplicate subsets** in the answer (guaranteed achievable here because input values are unique — more on why in §5.1).
- **Any order** of subsets is accepted, and element order *within* a subset follows input positions.

Key framing to say aloud: a "subset" is really a decision about **positions** — for each of the `n` positions, the element is either *in* or *out*. With unique values, position-subsets and value-subsets correspond one-to-one, which is why the problem is well-defined regardless of how `nums` is ordered.

## 2. Decoding the Constraints

| Constraint | What it's telling you | Implication for your solution |
|---|---|---|
| `1 <= nums.length <= 10` | Power set has at most `2^10 = 1024` subsets; total integers across all subsets ≤ `10 · 2^9 = 5120` | Exponential time is **expected, not a red flag** — the output itself is exponential in size, so no polynomial algorithm exists (see §7) |
| `-10 <= nums[i] <= 10` | Small-magnitude values | We never do arithmetic on values (only store them), so negatives are a non-issue; no overflow anywhere |
| All numbers unique | Each index subset maps to a unique value subset | **No sorting, no dedup, no `set` needed.** The `i + 1` recursion discipline alone guarantees "no duplicate subsets" |
| "Return the solution in any order" | Output ordering is free | DFS pre-order, bitmask counting order, iterative-doubling order — all acceptable |

Interview signal: whenever `n ≤ ~20` appears in a subset/combination problem, the interviewer is telling you *enumerate the power set* (or a bitmask DP) is the intended family of solutions.

## 3. Brute Force: Enumerate Every Membership Mask (with a worked trace)

The most direct translation of "every element in or out": loop over all `2^n` bitmasks. Bit `i` of the mask answers "is `nums[i]` in this subset?"

```python
def subsets_mask(nums: list[int]) -> list[list[int]]:
    n = len(nums)
    res = []
    for mask in range(1 << n):                      # 2**n masks: 0 .. 2**n - 1
        res.append([nums[i] for i in range(n) if mask >> i & 1])
    return res
```

**Worked trace on `[1,2,3]`** (bit `i` ↔ `nums[i]`):

| mask | binary | bits set | subset built |
|---|---|---|---|
| 0 | `000` | — | `[]` |
| 1 | `001` | 0 | `[1]` |
| 2 | `010` | 1 | `[2]` |
| 3 | `011` | 0,1 | `[1,2]` |
| 4 | `100` | 2 | `[3]` |
| 5 | `101` | 0,2 | `[1,3]` |
| 6 | `110` | 1,2 | `[2,3]` |
| 7 | `111` | 0,1,2 | `[1,2,3]` |

8 subsets, all distinct. This is correct and simple, but it always does `n` bit-checks per mask with no sharing of prefix work, and it's rigid: the moment the problem adds a constraint ("only size-k subsets", "subset sum ≤ T"), masks don't extend gracefully. That's the bridge to the optimal/interview-default approach.

## 4. The Core Insight

> **Think of the recursion as a binary decision tree over indices, where every node is a complete, valid answer.**

- Each call decides "which index do I commit next?" Starting from the empty set, each node of the tree is a subset; there are exactly `2^n` nodes.
- Unlike **permutations** (record only at leaves, path length `n`) or **combination sum** (record only when a target hits zero), here there is *no acceptance condition* — "I've run out of indices" is the only terminal state, so **you must snapshot the current path at entry to every call**, empty set included.
- Choices are made **by index, never by value**: recursion advances to `i + 1` (strictly past the index just chosen). Strictly increasing indices mean each index-subset is generated by exactly one root-to-node path — that's the entire duplicate-freedom argument.

This "record at every node" policy is the single most-skipped subtlety in this problem. Missing it costs you ~most of the answer.

## 5. Optimal Approach: Index-Based Backtracking

```python
from typing import List

def subsets(nums: List[int]) -> List[List[int]]:
    res: List[List[int]] = []
    path: List[int] = []                     # values chosen so far, in increasing index order

    def dfs(start: int) -> None:             # start = smallest index still choosable
        res.append(path[:])                  # EVERY node is a subset — snapshot a COPY
        for i in range(start, len(nums)):    # i is an INDEX into nums
            path.append(nums[i])             # choose the VALUE nums[i]
            dfs(i + 1)                       # recurse strictly past i -> no reuse, canonical
            path.pop()                       # un-choose before trying the next index
    dfs(0)
    return res
```

Equivalent "take/skip" formulation (same tree, more explicit binary choice):

```python
def subsets_binary(nums: List[int]) -> List[List[int]]:
    res, path, n = [], [], len(nums)

    def dfs(i: int) -> None:
        if i == n:                           # every index decided
            res.append(path[:])
            return
        path.append(nums[i])                 # TAKE nums[i]
        dfs(i + 1)
        path.pop()                           # SKIP nums[i]
        dfs(i + 1)
    dfs(0)
    return res
```

### 5.1 Why no duplicate subsets (indices vs values — say this explicitly)

- `i`, `start` are **indices**; `path` holds **values**. Never mix them up — e.g., never write "skip if this value is already in `path`"; that's a value-based filter that breaks with duplicate inputs and is unnecessary here.
- The loop `for i in range(start, n)` with recursion on `i + 1` enumerates each **subset of indices exactly once** (the indices along any root-to-node path are strictly increasing, and every index subset has exactly one such chain).
- Since input values are unique, distinct index subsets → distinct value subsets ⇒ **zero duplicate subsets, with no dedup machinery**. (The moment the interviewer says "what if duplicates?" → that's LC 90, Subsets II: sort, then skip `nums[i] == nums[i-1]` when `i > start`.)

### 5.2 Trace on Example 1: `nums = [1,2,3]`

Recursion tree — each node is one `dfs` call and one snapshot:

```
                         []   (dfs(0) -> record)
        ┌────────────┬───┴──────┐
      [1]           [2]         [3]      (record)
   ┌────┴─────┐       │
 [1,2]      [1,3]    [2,3]               (record)
   │
 [1,2,3]                                (record; loop finds nothing, return)
```

Pre-order recording order: `[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]` — 8 subsets ✓, matching the expected set (order is free).

### 5.3 Trace on Example 2: `nums = [0]` (take/skip variant)

```
dfs(0)
  take 0 -> dfs(1): i == n -> record [0]
  pop; skip -> dfs(1): i == n -> record []
```

Output `[[0], []]` ✓ — note the empty set is produced by the *skip-all* branch, a common place to accidentally lose it if you only record on "take" paths.

## 6. Two More Implementations You Should Know

### 6.1 Iterative doubling (matches Example 1's official output order *exactly*)

Every existing subset either contains the new element or it doesn't — so clone all current subsets, append the new element to the clones, and merge:

```python
def subsets_iter(nums: List[int]) -> List[List[int]]:
    res: List[List[int]] = [[]]
    for x in nums:
        res += [s + [x] for s in res]    # build the NEW list first, then extend
    return res
```

Trace on `[1,2,3]`:

| after processing | `res` |
|---|---|
| (start) | `[]` |
| `1` | `[], [1]` |
| `2` | `[], [1], [2], [1,2]` |
| `3` | `[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]` |

That final line is literally the official expected output, in order. Great "no recursion" option if the interviewer pushes on stack usage.

### 6.2 Bitmask version

See §3 — keep it in your pocket for related problems where you aggregate over subsets (e.g., "sum of XOR of all subsets", LC 1863): the mask loop generalizes to any per-subset computation.

## 7. Complexity

| Approach | Time | Auxiliary space (excl. output) | Output space | Notes |
|---|---|---|---|---|
| Bitmask (§3) | Θ(n · 2ⁿ) | Θ(n) (one reused temp) | Θ(n · 2ⁿ) | always does n bit-checks per mask |
| Backtracking (§5) | Θ(n · 2ⁿ) | Θ(n) path + Θ(n) recursion stack | Θ(n · 2ⁿ) | shares prefix work; extends to constrained variants |
| Iterative doubling (§6.1) | Θ(n · 2ⁿ) | Θ(1) beyond output | Θ(n · 2ⁿ) | shortest code; allocation churn per level |

- **Time:** the tree has exactly `2^n` nodes (one per subset); copying each subset at its node costs its length, and the sum of all subset lengths is `n · 2^(n−1)` — hence Θ(n · 2ⁿ), not just Θ(2ⁿ).
- **Lower bound (why you can't beat this):** any correct algorithm must write out `2^n` lists containing `n · 2^(n−1)` integers in total (each element appears in exactly half of all subsets), so Θ(n · 2ⁿ) is output-size-optimal — cite this in one sentence if the interviewer asks "can we do better?"
- Recursion depth is `n ≤ 10`, so stack depth is a non-issue in Python (default limit 1000; even n ≈ 20 would be fine).

## 8. Common Mistakes

| # | Mistake | Symptom | Fix |
|---|---|---|---|
| 1 | Recording only "complete" subsets (leaf-style, like permutations) | Output is missing nearly everything; often just `[[1,2,3]]` | Snapshot a copy at **entry to every** `dfs` call |
| 2 | `res.append(path)` (aliasing) | Every stored row ends up `[]` or identical — they're all the same mutated list | Append `path[:]` (or `list(path)`); in Java `new ArrayList<>(path)` |
| 3 | Recursing `dfs(start)` or `dfs(i)` instead of `dfs(i + 1)` | Reused elements → `[1,1]`-style duplicates; in take/skip form, **infinite recursion** | Always advance strictly past the chosen index |
| 4 | Forgetting `path.pop()` (or popping before recursing) | Later branches polluted with stale elements | Pop immediately after the recursive call returns |
| 5 | Iterative: `for s in res: res.append(s + [x])` | Hangs — you're appending into the list you're iterating, so newly added subsets get processed too | Build `new = [s + [x] for s in res]`, then `res += new` |
| 6 | Bitmask off-by-one: `range(2**n - 1)` | Missing the last subset (all bits set) | `range(1 << n)` covers masks `0 .. 2^n − 1` |
| 7 | Unnecessary sorting / `set`-of-tuples dedup | Wasted work; muddled correctness story | With unique inputs, the `i + 1` index discipline *is* the dedup argument |
| 8 | Assuming output must be sorted or match a specific order | Panic during verification | Problem says any order; compare as **sets of canonicalized subsets** in tests |

## 9. Language Gotchas Beyond Python (Java/C++)

- **Java — aliasing (same as Python mistake #2):** `res.add(path)` stores a live reference; every result row mutates together and ends up empty. Copy: `res.add(new ArrayList<>(path))`.
- **Java — autoboxing:** results live in `List<List<Integer>>`, so every `int` is boxed; if you ever dedup via `Set<List<Integer>>`, equality/hashCode works on contents, but never compare `Integer`s with `==` — use `equals` or unbox.
- **C++ — copies are your friend:** `path` should be passed by `vector<int>&` for speed, and `res.push_back(path)` copies by value (safe, unlike Java/Python references). The aliasing bug only reappears if you store pointers/references to `path`.
- **Overflow in bit tricks (general habit):** `1 << n` is fine for `n ≤ 10`, but the bitmask-enumeration pattern is only valid up to `n ≈ 30` in 32-bit `int` (`1 << 31` is UB in C++/wraps in Java) — use `1LL << n` in C++ when `n` can be larger.

## 10. Test Cases to State Out Loud

Propose these *before* coding — it signals rigor:

1. **Official Example 1:** `[1,2,3]` → the 8 subsets `[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]`.
2. **Official Example 2:** `[0]` → `[[], [0]]` — single element; also confirms the empty set is included.
3. **Negatives:** `[-1,-2]` → `[[], [-1], [-2], [-1,-2]]` — we only store values, never compute with them, so negatives must be safe.
4. **Max size `n = 10`:** don't eyeball content — verify *counts*: exactly `2^10 = 1024` subsets and total `10 · 2^9 = 5120` integers across them (each element appears in exactly half of all subsets).
5. **Unsorted input:** `[3,1,2]` — no sorting needed (values unique, order-free output); subsets like `[3,1]` are legitimate.

```python
def _canon(subsets):
    return sorted(sorted(s) for s in subsets)      # order-insensitive comparison

def test_subsets():
    assert _canon(subsets([1, 2, 3])) == _canon([[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]])
    assert _canon(subsets([0])) == _canon([[], [0]])
    assert _canon(subsets([-1, -2])) == _canon([[], [-1], [-2], [-1, -2]])     # negatives
    assert _canon(subsets([3, 1, 2])) == _canon(subsets([1, 2, 3]))            # unsorted input
    big = subsets(list(range(10)))                                             # n = 10 (max)
    assert len(big) == 2 ** 10                       # exactly 1024 subsets
    assert sum(len(s) for s in big) == 10 * 2 ** 9   # 5120 total elements across output
```

## 11. Transferable Patterns & Related Problems

**The pattern:** *subset-style backtracking* — iterate candidate indices from `start`, choose → recurse with `i + 1` → un-choose. What changes between problems is only the **recording policy** (every node vs. leaves vs. condition met) and any **pruning**.

| Problem | Relation | Twist |
|---|---|---|
| LC 90 Subsets II | same skeleton | duplicates in input → sort + skip `nums[i] == nums[i-1]` when `i > start` |
| LC 77 Combinations | subsets of fixed size k | record only when `len(path) == k`; prune loop bound when remaining elements can't reach k |
| LC 39 / 40 Combination Sum I/II | same skeleton | reuse allowed → recurse `dfs(i)` not `i + 1`; II adds the dedup rule |
| LC 46 Permutations | sibling pattern | order matters → use a `used[]` set instead of `start`; record at leaves |
| LC 784 Letter Case Permutation | binary take/skip tree | per-character in/out choice, identical shape |
| LC 320 Generalized Abbreviation | binary tree + count collapsing | choose "keep" vs "abbreviate run" per position |
| LC 1863 Sum of All Subset XOR Totals | bitmask application | aggregate a value over the same `2^n` masks |

**Follow-ups to expect in the interview:**
- *"What if there are duplicates?"* → sort + same-level skip (LC 90); mention count-based alternative.
- *"Only subsets of size k?"* → record on `len(path) == k`, prune the loop upper bound.
- *"Can you avoid storing everything?"* → stream with a generator (`yield path[:]` at each node); memory is dominated by the output either way.
- *"Count subsets with property X?"* → don't materialize; return counts up the recursion (or bitmask DP when n ≤ ~20).

## 12. Full Interview Talk Track (script)

> "Let me restate: I need the full power set of distinct elements, including the empty subset, no duplicate subsets, any order.
>
> Constraints first: n ≤ 10, so there are at most 2¹⁰ = 1024 subsets and about 5120 integers in the whole output. Since each element belongs to exactly half of all subsets, the output itself has size Θ(n · 2ⁿ), so exponential time is not just acceptable — it's provably optimal.
>
> My approach is index-based backtracking. I keep a `path` of chosen values and a `start` index. At the entry to every call I snapshot a **copy** of `path` into the result — that's the key subtlety: unlike permutations, **every** node of this decision tree is a complete answer, including the empty set. Then I loop `i` from `start` to the end, append `nums[i]`, recurse with `i + 1`, and pop.
>
> Why no duplicates: choices are made by index and strictly increase, so every index-subset is generated by exactly one root-to-node path; values are unique, so distinct index subsets give distinct value subsets. No dedup machinery needed.
>
> Complexity: time Θ(n · 2ⁿ) because the tree has 2ⁿ nodes and copying costs sum to n · 2ⁿ⁻¹; auxiliary space Θ(n) for the path and stack, plus the output.
>
> Tests: the two official examples; negatives like `[-1,-2]`; unsorted input; and at n = 10 I'd assert exactly 1024 subsets and 5120 total elements rather than eyeballing."

> "Each element is either in a subset or out, so there are 2ⁿ subsets — with n ≤ 10, that's at most 1024, and since the output itself is that big, Θ(n · 2ⁿ) is the optimal complexity, not a red flag.
